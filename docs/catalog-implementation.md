## 更新方法と期限切れ

今回は**公開ストアの手動同期**。定期同期・API接続・Webhookを稼働させたとは扱わない。

1. `npm run sync:public` で全公開商品を再取得。全件成功・前後の一覧一致時だけ置換する。
2. `npm run validate:catalog` で情報・画像・リンクを検証し対応表を生成。
3. `npm run build:catalog:site` で公開用出力を生成。GitHub反映と本番公開は別操作。

価格と売り切れは「確認時」と時刻を併記。取得から24時間後のリクエストでは価格・売り切れ判定を表示せず、BASE確認案内に切り替える。JavaScript有効なら開いたままのページも切り替える。説明原文には取得時点の日時を付ける。

同期失敗は終了コード1とエラーを表示し、`public-sync-status.json` に記録。本番ビルドは失敗状態・未検証データを拒否する。古いデータの確認日時を更新しない。外部メール通知は設定していない。

公開一覧から消えた商品は次の正常同期後に除外し、詳細404・サイトマップ除外。削除と非公開は公開ストアでは区別できず、即時反映ではない。BASE更新後に再同期する運用が必要。

## SEO

固有title・description・H1・self-canonical・OG、Product/Brand/BreadcrumbListを実装。本番の公開商品はindex、絞り込みURLはnoindexで主一覧をcanonical、確認用ページはnoindex。通常の内部リンク・alt・パンくず・商品サイトマップ・404を備える。

公開ストア方式では、未検証の在庫や古い価格をOfferとして残さないためOfferを出さない。公式API方式には最新の価格・在庫と一致するOfferを実装済みだが、実接続は未実施。架空のレビュー・評価・GTIN等を出さない。

購入完了が外部BASEのため、[Google販売者リスティング](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing) 対応済みとはしない。現在の方式で[商品スニペット](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)のリッチ表示を得られるとも主張しない。

BASEの商品事実と説明を維持し、画像・仕様へのアクセス、ブランド比較、関連商品で閲覧上の価値を追加。根拠のない独自文章を生成しない。[canonicalの公式ガイド](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)のとおり、正規URL指定はGoogleの選択を保証しない。BASEとの重複による別URL選択の可能性は残る。順位や登録を保証しない。

## 公式API・CSV・画像配信の調査

[BASE API v2](https://apiv2.thebase.com/docs/) の読取専用アダプターを実装。PATはサーバー環境変数で管理し、items.readとショップ照合用user.readのみ使用する。[商品一覧API](https://apiv2.thebase.com/docs/endpoints/get-api-items/) で公開・非公開を含めて全ページを2回取得し、一致しない場合は中断する。API方式の失敗時は古い情報を返さず503にする。

[公開API一覧](https://apiv2.thebase.com/docs/reference/) に商品更新Webhookは確認できていない。認証が使えない場合の代替には[CSV商品管理App](https://help.thebase.in/hc/ja/articles/900000043803)のダウンロードがあるが、今回はユーザー指定で公開ストアを使用した。

画像はBASE公開元URLを利用。[API利用規約](https://thebase.com/pages/api_term)・画像仕様を確認したが、外部直リンクの恒久的な保証、URLの有効期限の保証は確認できていない。配信障害・URL変更には再同期が必要。許諾済み画像の自サイト保存は外部依存を減らす一方、更新・削除の追随が必要。今回追加分は直接配信、既存Collection/LookbookのWebPは従来のローカル配信を維持する。
